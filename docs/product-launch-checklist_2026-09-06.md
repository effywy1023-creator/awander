# 新产品上线检查清单

> 项目：gentle-lore v2 | 提出人：Effy | 日期：2026-09-06
> 背景：见 [`prd-multi-product-config_2026-09-05.md`](./prd-multi-product-config_2026-09-05.md)

---

## 为什么需要这份清单

`app_config` 的文案分层是**按 key 逐条 opt-in 覆盖**的：`product_id` 为空 = 全局默认值，有值 = 该产品专属覆盖值。

这意味着：**新产品上线时，系统不会自动提醒你哪些文案需要覆盖**。没人主动配置的话，新产品会直接继承现在这 20 多条全局默认值——而这些默认值目前基本都是照着"身体藏宝图"的世界观写的（藏宝、挖掘、金库、宝箱……）。不会报错、不会空白，但措辞会跟错产品。

`map_title`、`medal_title` 两次踩坑都是这个原因：全局默认值里点名了"藏宝图"，新产品没人覆盖，就直接把这行字带过去了。

这份清单就是为了在下一个产品上线前，把这类"点名式"文案一次性排查掉。

---

## 一、上线前必做

### 1. 数据库准备（DML，不涉及 DDL）

- [ ] `products` 表插入新产品行，确认 `default_view` 字段设对（有清晰前后依赖路径 → `map`；关卡互相独立、更像自由探索 → `list`）
- [ ] `routes` 表插入该产品的航线，`level_ids` 按顺序列好
- [ ] `levels` 表里该产品所有关卡的 `product_id` 都指向新产品
- [ ] 需要解锁依赖的关卡设好 `parent_id`；无依赖关系的关卡 `parent_id` 留空（默认解锁）
- [ ] `user_products` 表给需要开通的学员/测试账号插入访问权限

### 2. 文案审查（这份清单的核心）

过一遍 `app_config` 里**全局默认值（`product_id IS NULL`）**，凡是提到具体产品名、具体世界观意象（藏宝图/挖掘/宝箱/金库/探险等）的 key，都要为新产品插入一条专属覆盖：

```sql
INSERT INTO app_config (key, value, description, product_id)
VALUES ('<key>', '<新产品的文案>', '<说明>', '<新产品 uuid>');
```

**已知需要重点检查的 key**（截至 2026-09-06，做觉察游乐园时发现的清单，以实际 `app_config` 表内容为准）：

| key | 当前全局值 | 备注 |
|---|---|---|
| `map_title` | 身体藏宝图 | 地图页大标题，最显眼，必须覆盖 |
| `medal_title` | 你已完成全部藏宝图关卡 | "全部完成"弹窗主标题，点名藏宝图 |
| `medal_subtitle` | 太棒了！ | 弹窗副标题，通用性尚可，看情况覆盖 |
| `medal_body` | 除了彩蛋之外～🐟 | 弹窗正文，通用性尚可，看情况覆盖 |
| `log_section_title` | 藏宝日志 | 点名"藏宝" |
| `writing_section_title` | 挖掘今日宝藏 | "挖掘宝藏"意象 |
| `save_button` | 存入金库 💰 | "金库"意象 |
| `status_digging` | 正在挖掘... | "挖掘"意象 |
| `history_log_title` | 探险日志回响 | 探险/藏宝调性 |
| `map_subtitle` | 首批探险家的秘密 | 探险调性 |
| `writing_placeholder` | ...或许去问问小鱼？ | 提到藏宝图角色"小鱼" |
| `empty_log_hint` | ...快去挖掘你的第一件宝藏吧！ | "挖掘宝藏"意象 |

> `login_title` / `login_subtitle` / `login_button` **不需要覆盖**——按设计这三个是登录前（还没选产品）的全局兜底，所有产品共用同一套是预期行为。

**没想好新产品专属文案、又不想显示藏宝图措辞的 key**：可以插入一条**空字符串**的覆盖值。`t(key, fallback)` 遇到空字符串会自动跳到代码里的通用兜底文案（不带任何产品名的中性说法），不会显示空白，也不会读到藏宝图默认值。示例见下方"举例"。

### 3. 视图与统计（代码已支持，一般不需要额外操作）

- [ ] 确认 `products.default_view` 设置符合预期（`list` 会隐藏地图/列表切换 tab、隐藏"第 N 站"编号）
- [ ] 地图页统计（探索时间/探索线索）、`/notes`、`/admin/notes` 的产品名标签都是自动按 `levels.product_id` 关联出来的，新产品上线后不需要改代码

### 4. 测试

- [ ] 用一个双产品测试账号（同时拥有新产品 + 至少一个老产品）登录，走一遍新产品的完整关卡流程（进入地图、播放音频、提交写作、触发"全部完成"弹窗），确认没有任何文案点名了别的产品
- [ ] 确认切换回老产品后，视图偏好、统计口径、文案都没被新产品影响（参照 [`prd-multi-product-config_2026-09-05.md`](./prd-multi-product-config_2026-09-05.md) 的"视图状态隔离"验收标准）
- [ ] 单产品权限的老账号（只有藏宝图或只有 A new land）重新登录检查一遍，确认改动没有影响到他们

## 二、举例：某个 key 想用中性兜底而不是藏宝图默认值

假设新产品叫「星辰岛」，`medal_body` 想直接用代码里的通用兜底文案（不想写新词，也不想显示"除了彩蛋之外～🐟"）：

```sql
INSERT INTO app_config (key, value, description, product_id)
VALUES ('medal_body', '', '星辰岛沿用通用兜底文案', '<星辰岛 uuid>');
```

## 三、这份清单之外，还没排期的事

以下问题跟新产品上线没有直接关系，但会在产品数量变多之后更容易暴露，记在这里备查：

- 一个产品只能有一条航线（`routes` 查询用 `.single()`），分批次推送内容会失效——[PRD 后续依赖需求](./prd-multi-product-config_2026-09-05.md#七后续依赖需求挂起)已记录
- 无坐标关卡（`levels.x/y` 为空）在地图视图下会重叠，新产品若用地图视图要注意建关卡时把坐标填好
- 关卡图标按中文名硬编码映射，新关卡名字没匹配到会显示默认 MapPin 图标，不算错误但不够精致
- RLS 仍未开启，所有表对 anon key 可读写——优先级高于以上所有事项，独立立项处理
